# SchedulePin 插件与桌面助手架构

## 1. 本次迁移的目标

SchedulePin 不再把可交互 WebView 窗口伪装成桌面组件。产品拆分为一个可以独立工作的浏览器插件，以及一个仅在需要 Windows 桌面壁纸能力时安装的本地助手。

- 浏览器插件是主产品：负责新标签页、侧边栏、任务编辑、设置和主数据存储。
- 本地助手是可选扩展：负责读取显示器、备份壁纸、生成计划壁纸、应用和恢复壁纸。
- 没有安装本地助手时，插件的任务管理、新标签页和侧边栏仍然完整可用。
- 桌面只展示，不接受鼠标操作，也不存在窗口拖动、缩放、置顶或焦点问题。

## 2. 技术栈变更

### 2.1 放弃的部分

| 技术或组件 | 原用途 | 放弃原因 |
| --- | --- | --- |
| 可见 Tauri WebView 窗口 | 同时承载任务编辑和桌面展示 | 与“桌面只展示”冲突，并产生焦点、拖动、缩放和关闭问题 |
| WorkerW / Progman 子窗口嵌入 | 模拟桌面组件层 | 属于易受 Explorer、DPI、父窗口裁剪和多屏坐标影响的窗口技巧 |
| `always_on_bottom` 窗口层级模拟 | 让组件位于应用窗口下方 | 无法像壁纸一样保证绝不出现在普通应用之上 |
| Tauri SQL 与前端直连 SQLite | 桌面窗口中的任务存储 | 浏览器插件不能直接使用这套原生插件；主数据应随插件独立存在 |
| 前端原生拖动、八方向缩放 | 调整真实桌面窗口 | 改为在浏览器的显示器预览画布中编辑布局 |
| 本地 HTTP 管理端口 | 让浏览器访问桌面程序 | 插件已经提供管理界面，Native Messaging 更窄、更安全，不必暴露端口 |

### 2.2 保留的部分

| 技术或能力 | 新用途 |
| --- | --- |
| React | 新标签页、侧边栏和设置界面 |
| TypeScript | 任务模型、插件逻辑和通信协议类型 |
| Vite | 构建 Manifest V3 插件资源 |
| Rust | 编写体积小、无编辑窗口的 Windows 助手 |
| 本地优先原则 | 默认不登录、不上传任务，数据留在本机 |
| To-Do 与 Principle 数据模型 | 插件统一编辑；To-Do 按自定义顺序持续保留，Principle 作为独立段落保存 |

### 2.3 新增的部分

| 技术或组件 | 用途 |
| --- | --- |
| Manifest V3 | Chrome / Edge 浏览器插件运行模型 |
| New Tab Override | 打开新标签页时显示文字导航与完整计划总览 |
| Side Panel | 浏览网页时随时打开任务面板 |
| `chrome.storage.local` | 插件的主数据源；助手缺失时仍可独立工作 |
| Extension Service Worker | 监听数据变化、定时刷新和连接本地助手 |
| Native Messaging | 插件与助手之间的受限 JSON 消息通道 |
| SVG + PNG 壁纸渲染 | 按显示器分辨率生成静态桌面计划 |
| Windows `IDesktopWallpaper` | 逐屏读取、应用和恢复壁纸 |
| 助手状态缓存 | 浏览器关闭后保留最后一次计划快照和原壁纸信息 |
| `dnd-kit` | 提供跟随指针、相邻任务让位和键盘可访问的排序交互 |
| GitHub Actions / Releases | 使用 Standard Windows Runner 手动构建或按版本标签发布 Helper 安装程序 |
| 固定开发扩展 ID | 通过 `manifest.key` 保持本地测试 ID 稳定，安装脚本无需用户传参 |
| Inno Setup | 把 Helper、Native Messaging 注册、开机启动和安全卸载封装为单文件安装程序 |
| 共用 Release 脚本 | 本地和 GitHub 调用相同入口，只产出 `SchedulePin-Helper-Setup.exe` |

## 3. 运行架构

```text
Chrome / Edge 浏览器插件
├─ 新标签页（导航与计划双栏，可分别滚动）
├─ 侧边栏（可另开完整页面）
├─ 分类设置中心
│  ├─ 快捷访问管理与新标签页偏好
│  ├─ 外观草稿与横屏 / 竖屏 / 侧边栏共享组件预览
│  ├─ Principle 编辑
│  └─ 桌面与显示器布局预览
├─ chrome.storage.local（主数据）
└─ Service Worker
          │
          │ Native Messaging（助手可用时）
          ▼
SchedulePin Helper.exe
├─ 协议校验与能力查询
├─ 最后计划快照缓存
├─ 显示器枚举
├─ 原壁纸状态备份
├─ SVG/PNG 壁纸生成
└─ IDesktopWallpaper 调用
          │
          ▼
Windows 每块显示器的桌面壁纸
```

## 4. 数据所有权与同步

插件是唯一的任务主数据源。本地助手不能新增、修改或删除任务，只接收插件发来的渲染快照。

1. 用户在新标签页或侧边栏修改计划。
2. 插件先把变更写入 `chrome.storage.local`。
3. Service Worker 合并短时间内的连续变更，然后向助手发送最新完整快照。
4. 助手持久化快照，生成临时 PNG。
5. PNG 完整生成到新的唯一文件后，再通知 Windows 切换；生成失败时仍保留上一张有效壁纸。
6. 失败时保留上一张有效壁纸，并向插件返回可读错误。

助手未安装或未运行时，第 3 步只把桌面状态标记为“未连接”，不会影响前两步。

任务界面只保留两层信息：醒目的 `Principle` 段落和一张连续的 To-Do List。快速输入框位于列表末尾并通过 Enter 添加；任务默认按添加顺序排列，也可用左侧手柄动态调整并持久化。完成的 To-Do 当天保留删除线，跨日加载时自动归档；独立归档页按完成日期分组，并支持搜索、恢复和永久删除。旧版“今日重点”“时间安排”“纪律打卡”和“备忘”不再作为独立模块展示。

外观设置随主数据保存在 `chrome.storage.local`，包括页面主题、全局字体、字号、界面密度和卡片圆角；Principle 的背景主题、字体、字号和文字样式作为独立字段保存，不受全局字体设置影响。进入独立外观编辑器后，修改先保存在组件草稿中，并通过只读的真实数据预览分别模拟新标签页与侧边栏；只有点击“保存”才写入存储并应用到浏览器页面，点击“取消”则丢弃草稿。网页与桌面助手共同读取 `shared/visual-design.json` 中的主题色、表面色和 Principle 配色，保持同一设计语言；桌面助手再按实际显示区域独立换算字号、测量中英文宽度和自适应卡片高度，而不是复制网页的绝对像素。桌面静态壁纸按网页相同的品牌栏、日期进度、Principle 和 To-Do 卡片层级生成，仅省略按钮、输入框、勾选框和拖动手柄等交互控件。

新标签页由 `NewTabLayout` 组织 `ShortcutPanel` 和 `PlanView`，侧边栏及 `?view=plan` 完整计划入口复用 `PlanView`。导航宽度控制在 220–260 CSS 像素左右，按实际容器宽度决定是否并排；横竖方向本身不触发单栏。导航和计划分别滚动，计划区的 Principle 与 To-Do 共用一个滚动容器。

快捷访问使用独立键 `schedulepin.navigation.v1`，保存有序链接和分组；`schedulepin.newtab.v1` 保存导航位置、域名显示、完整待办、Principle 和分组展开状态。写入通过 Web Locks 序列化，订阅存储事件更新其他标签页。删除分组只解除归属，不删除链接；网址只接受 HTTP / HTTPS。Service Worker 仍只监听原有任务与设置键，导航整理与新标签页偏好不会触发壁纸同步，也不进入助手快照。

`AppearancePreview` 在独立 iframe 文档内复用导航、双栏布局和计划组件，使媒体查询基于模拟视口计算，且隔离编辑器当前主题；预览使用真实数据且不可编辑，不写入导航或任务。外观草稿仍只有保存后才写入原有设置键。

链接的 `title` 为空时由 `linkTitle` 动态读取域名，不把默认名称固化进存储；编辑网址时自动更新，已有名称原样保留。`SiteIcon` 先显示按域名生成的字母，再通过 `siteIcons.ts` 查询浏览器 `_favicon`，比较默认占位图像后决定是否尝试站点自身的 `/favicon.ico`。图片不发送来源页地址、不使用第三方图标服务，也不抓取网站正文；失败与成功结果分别在页面内短期缓存，加载设有超时。只有 `favicon` 权限新增到扩展，导航数据仍不进入桌面快照。

导航的柔和渐变、分组标记、输入焦点和小型任务进度环复用现有主题色；图标保留网站原色，字母底色由域名稳定映射。导航行保持文字列表，外观密度和圆角继续生效；尊重系统减少动画的偏好。

入口搜索在可编辑导航挂载期间监听 `/`，排除文字输入、组合键、输入法组合和弹窗。排序使用独立手柄与 dnd-kit 的指针 / 键盘传感器，在当前可见分组内执行插入式重排；搜索期间禁用拖动，分组外条目的位置和归属不变。

新标签页背景使用独立 IndexedDB `schedulepin.background.v1`，`preferences` 保存风格、轮换与裁切，`wallpapers` 保存 JPEG 图片 Blob、缩略图、署名许可和收藏标记。Web Locks 序列化写入，BroadcastChannel 只同步全局偏好与图库变更；纯缓存写入不会要求其他标签页重读图片 Blob。背景不进入原有 `AppSettings` 或桌面快照。保存选定背景与图片在同一事务中完成，旧请求用 revision 检查避免覆盖较新的选择。自动轮换只在打开页面时判断；“每次打开或刷新”模式将实际显示项保存在窗口状态和 `sessionStorage` 中，自动或手动换图不写回全局 `currentId`，因此不会切换已有窗口。固定与每日模式仍使用全局选择。处理图片期间先保留当前背景，并等待输入 / 弹窗结束才应用。

`WallpaperPage` 使用共享 `AppearancePreview`，其草稿只有“保存背景”才生效；上传、收藏和删除独立即时写入图库。收藏只改变保存状态，固定只改变轮换模式；固定情况下手动换图需先预览候选。收藏图片不自动清理，非收藏的最近缓存保留当前及另外六张。备份携带实际图片与作者许可信息，导入先验证并处理全部图片，再原子写入；备份不覆盖现有背景设置。清除浏览器站点数据或卸载扩展仍会清除 IndexedDB。

在线来源采用 Wikimedia Commons Action API 的 imageinfo 与许可元数据，仅接受公共领域、CC0、CC BY 和 CC BY-SA 的位图结果。图片下载只允许 `upload.wikimedia.org` 与 `thumb.wikimedia.org`，扩展新增这两个域名及 `commons.wikimedia.org` 的访问权限；不发送账户 Cookie 或来源页地址。图片处理会优化尺寸，预览与来源说明标明这一点，原作者、许可与原始页面链接保留。没有后端或私有 API 密钥，在线失败时仍可使用本地图库。

## 5. 壁纸备份和恢复

第一次启用桌面计划时，助手按显示器 ID 保存：

- 原壁纸路径和一份可恢复的文件副本；
- 壁纸位置模式；
- 计划展示开关；
- 当前显示器布局。

只要原始备份已经存在，后续刷新计划不得用 SchedulePin 生成图覆盖它。用户可以执行：

- 暂时恢复原壁纸：保留助手和任务，只关闭桌面展示；
- 重新显示桌面计划：用最新计划重新生成；
- 退出并恢复原壁纸：恢复后停止助手；
- 卸载助手：先恢复壁纸，再清理注册和生成文件。

如果助手异常退出，Windows 会继续显示最后一张有效壁纸。下次连接助手后仍可使用持久化备份恢复。

## 6. 布局与多显示器

真实桌面不再接受拖动。插件设置页显示每块屏幕的比例预览，计划卡片在预览中使用百分比坐标：

```json
{
  "x": 0.68,
  "y": 0.06,
  "width": 0.28,
  "height": 0.82
}
```

助手收到快照后，把百分比转换为对应显示器的物理像素。因此更换分辨率或缩放比例后，布局仍保持相同的相对位置。用户可以指定单屏、全部屏幕，并为每块屏幕保存独立布局。

## 7. 可选安装模型

### 仅插件

- 不安装任何本地程序；
- 新标签页、侧边栏和任务管理正常使用；
- 桌面设置显示“未安装助手”；
- 不读取或修改 Windows 壁纸。

### 插件 + 助手

- 安装程序本体与助手安装在 `%LOCALAPPDATA%\Programs\SchedulePin Helper`；
- 运行状态、生成壁纸和原壁纸备份保存在 `%LOCALAPPDATA%\SchedulePin`；
- Native Messaging 清单只允许指定的扩展 ID 访问；
- 插件检测成功后解锁桌面设置；
- 单文件安装包可由本地脚本或 GitHub Standard Runner 构建，正式版本托管到 GitHub Releases。

开发版原文件位于 `native-helper/target/release/schedulepin-helper.exe`；本地完整联调仍使用开发安装脚本。正式交付只提供 `SchedulePin-Helper-Setup.exe`，用户无需接触裸 Helper、注册脚本或扩展 ID。项目不依赖自建下载服务器，GitHub Releases 保存正式安装程序。

## 8. 安全边界

- 不开放局域网或公网端口。
- Native Messaging Host 使用 `allowed_origins` 限制扩展 ID。
- 助手只接受固定协议中的查询、同步、应用和恢复命令。
- 任务内容不会由助手上传。
- 生成文件、缓存和壁纸备份均保存在当前用户的本地应用数据目录。

## 9. 第一版验收标准

- 插件可作为未打包 Chrome / Edge 扩展加载。
- 新标签页与侧边栏都能管理同一份任务数据，侧边栏可另开完整页面。
- 未安装助手时插件无报错并显示清楚的可选安装状态。
- 安装助手后插件能读取显示器列表。
- 插件保存计划后助手自动生成并应用新壁纸。
- 单屏和全部屏幕模式均可生成壁纸。
- 关闭桌面展示能恢复启用前的逐屏壁纸。
- 浏览器布局预览支持移动和缩放计划卡片。
- 本地助手不创建任何可见编辑窗口。

## 10. 第一版边界

- 旧 Tauri / SQLite 原型数据不自动迁移；浏览器插件从自己的本地存储开始工作。
- 原壁纸恢复覆盖逐屏图片、壁纸位置模式和背景色；Windows 壁纸轮播会恢复为启用当时捕获的静态图片，不会自动重新启动轮播。
- 当前插件仍以开发者加载方式使用；助手已具备本地与 GitHub 共用的单文件安装程序构建流程。
