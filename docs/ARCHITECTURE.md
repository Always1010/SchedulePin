# SchedulePin 插件与桌面助手架构

## 1. 本次迁移的目标

SchedulePin 不再把可交互 WebView 窗口伪装成桌面组件。产品拆分为一个可以独立工作的浏览器插件，以及一个仅在需要 Windows 桌面壁纸能力时安装的本地助手。

- 浏览器插件是主产品：负责新标签页、侧边栏、任务编辑、设置和主数据存储。
- 本地助手是可选扩展：负责读取显示器、备份壁纸、生成计划壁纸、应用和恢复壁纸。
- 没有安装本地助手时，插件的任务管理、新标签页和侧边栏仍然完整可用。
- 桌面只展示，不接受鼠标操作，也不存在窗口拖动、缩放、置顶或焦点问题。

## 2. 技术栈变更

### 2.1 放弃的部分

| 技术或组件 | 原用途 | 放弃原因 |
| --- | --- | --- |
| 可见 Tauri WebView 窗口 | 同时承载任务编辑和桌面展示 | 与“桌面只展示”冲突，并产生焦点、拖动、缩放和关闭问题 |
| WorkerW / Progman 子窗口嵌入 | 模拟桌面组件层 | 属于易受 Explorer、DPI、父窗口裁剪和多屏坐标影响的窗口技巧 |
| `always_on_bottom` 窗口层级模拟 | 让组件位于应用窗口下方 | 无法像壁纸一样保证绝不出现在普通应用之上 |
| Tauri SQL 与前端直连 SQLite | 桌面窗口中的任务存储 | 浏览器插件不能直接使用这套原生插件；主数据应随插件独立存在 |
| 前端原生拖动、八方向缩放 | 调整真实桌面窗口 | 改为在浏览器的显示器预览画布中编辑布局 |
| 本地 HTTP 管理端口 | 让浏览器访问桌面程序 | 插件已经提供管理界面，Native Messaging 更窄、更安全，不必暴露端口 |

### 2.2 保留的部分

| 技术或能力 | 新用途 |
| --- | --- |
| React | 新标签页、侧边栏和设置界面 |
| TypeScript | 任务模型、插件逻辑和通信协议类型 |
| Vite | 构建 Manifest V3 插件资源 |
| Rust | 编写体积小、无编辑窗口的 Windows 助手 |
| 本地优先原则 | 默认不登录、不上传任务，数据留在本机 |
| To-Do 与 Principle 数据模型 | 插件统一编辑；To-Do 按自定义顺序持续保留，Principle 作为独立段落保存 |

### 2.3 新增的部分

| 技术或组件 | 用途 |
| --- | --- |
| Manifest V3 | Chrome / Edge 浏览器插件运行模型 |
| New Tab Override | 打开新标签页时显示今日计划 |
| Side Panel | 浏览网页时随时打开任务面板 |
| `chrome.storage.local` | 插件的主数据源；助手缺失时仍可独立工作 |
| Extension Service Worker | 监听数据变化、定时刷新和连接本地助手 |
| Native Messaging | 插件与助手之间的受限 JSON 消息通道 |
| SVG + PNG 壁纸渲染 | 按显示器分辨率生成静态桌面计划 |
| Windows `IDesktopWallpaper` | 逐屏读取、应用和恢复壁纸 |
| 助手状态缓存 | 浏览器关闭后保留最后一次计划快照和原壁纸信息 |
| `dnd-kit` | 提供跟随指针、相邻任务让位和键盘可访问的排序交互 |
| GitHub Actions / Releases | 使用 Standard Windows Runner 手动构建或按版本标签发布 Helper 安装程序 |
| 固定开发扩展 ID | 通过 `manifest.key` 保持本地测试 ID 稳定，安装脚本无需用户传参 |
| Inno Setup | 把 Helper、Native Messaging 注册、开机启动和安全卸载封装为单文件安装程序 |
| 共用 Release 脚本 | 本地和 GitHub 调用相同入口，只产出 `SchedulePin-Helper-Setup.exe` |

## 3. 运行架构

```text
Chrome / Edge 浏览器插件
├─ 新标签页
├─ 侧边栏
├─ 设置与显示器布局预览
├─ chrome.storage.local（主数据）
└─ Service Worker
          │
          │ Native Messaging（助手可用时）
          ▼
SchedulePin Helper.exe
├─ 协议校验与能力查询
├─ 最后计划快照缓存
├─ 显示器枚举
├─ 原壁纸状态备份
├─ SVG/PNG 壁纸生成
└─ IDesktopWallpaper 调用
          │
          ▼
Windows 每块显示器的桌面壁纸
```

## 4. 数据所有权与同步

插件是唯一的任务主数据源。本地助手不能新增、修改或删除任务，只接收插件发来的渲染快照。

1. 用户在新标签页或侧边栏修改计划。
2. 插件先把变更写入 `chrome.storage.local`。
3. Service Worker 合并短时间内的连续变更，然后向助手发送最新完整快照。
4. 助手持久化快照，生成临时 PNG。
5. PNG 完整生成到新的唯一文件后，再通知 Windows 切换；生成失败时仍保留上一张有效壁纸。
6. 失败时保留上一张有效壁纸，并向插件返回可读错误。

助手未安装或未运行时，第 3 步只把桌面状态标记为“未连接”，不会影响前两步。

任务界面只保留两层信息：醒目的 `Principle` 段落和一张连续的 To-Do List。快速输入框位于列表末尾并通过 Enter 添加；任务默认按添加顺序排列，也可用左侧手柄动态调整并持久化。完成的 To-Do 当天保留删除线，跨日加载时自动归档；独立归档页按完成日期分组，并支持搜索、恢复和永久删除。旧版“今日重点”“时间安排”“纪律打卡”和“备忘”不再作为独立模块展示。

外观设置随主数据保存在 `chrome.storage.local`，包括主题、字体、字号、界面密度和卡片圆角。浏览器页面即时应用全部外观选项；桌面助手同步使用 Principle、字号、字体和圆角生成壁纸。

## 5. 壁纸备份和恢复

第一次启用桌面计划时，助手按显示器 ID 保存：

- 原壁纸路径和一份可恢复的文件副本；
- 壁纸位置模式；
- 计划展示开关；
- 当前显示器布局。

只要原始备份已经存在，后续刷新计划不得用 SchedulePin 生成图覆盖它。用户可以执行：

- 暂时恢复原壁纸：保留助手和任务，只关闭桌面展示；
- 重新显示桌面计划：用最新计划重新生成；
- 退出并恢复原壁纸：恢复后停止助手；
- 卸载助手：先恢复壁纸，再清理注册和生成文件。

如果助手异常退出，Windows 会继续显示最后一张有效壁纸。下次连接助手后仍可使用持久化备份恢复。

## 6. 布局与多显示器

真实桌面不再接受拖动。插件设置页显示每块屏幕的比例预览，计划卡片在预览中使用百分比坐标：

```json
{
  "x": 0.68,
  "y": 0.06,
  "width": 0.28,
  "height": 0.82
}
```

助手收到快照后，把百分比转换为对应显示器的物理像素。因此更换分辨率或缩放比例后，布局仍保持相同的相对位置。用户可以指定单屏、全部屏幕，并为每块屏幕保存独立布局。

## 7. 可选安装模型

### 仅插件

- 不安装任何本地程序；
- 新标签页、侧边栏和任务管理正常使用；
- 桌面设置显示“未安装助手”；
- 不读取或修改 Windows 壁纸。

### 插件 + 助手

- 安装程序本体与助手安装在 `%LOCALAPPDATA%\Programs\SchedulePin Helper`；
- 运行状态、生成壁纸和原壁纸备份保存在 `%LOCALAPPDATA%\SchedulePin`；
- Native Messaging 清单只允许指定的扩展 ID 访问；
- 插件检测成功后解锁桌面设置；
- 单文件安装包可由本地脚本或 GitHub Standard Runner 构建，正式版本托管到 GitHub Releases。

开发版原文件位于 `native-helper/target/release/schedulepin-helper.exe`；本地完整联调仍使用开发安装脚本。正式交付只提供 `SchedulePin-Helper-Setup.exe`，用户无需接触裸 Helper、注册脚本或扩展 ID。项目不依赖自建下载服务器，GitHub Releases 保存正式安装程序。

## 8. 安全边界

- 不开放局域网或公网端口。
- Native Messaging Host 使用 `allowed_origins` 限制扩展 ID。
- 助手只接受固定协议中的查询、同步、应用和恢复命令。
- 任务内容不会由助手上传。
- 生成文件、缓存和壁纸备份均保存在当前用户的本地应用数据目录。

## 9. 第一版验收标准

- 插件可作为未打包 Chrome / Edge 扩展加载。
- 新标签页与侧边栏都能管理同一份任务数据。
- 未安装助手时插件无报错并显示清楚的可选安装状态。
- 安装助手后插件能读取显示器列表。
- 插件保存计划后助手自动生成并应用新壁纸。
- 单屏和全部屏幕模式均可生成壁纸。
- 关闭桌面展示能恢复启用前的逐屏壁纸。
- 浏览器布局预览支持移动和缩放计划卡片。
- 本地助手不创建任何可见编辑窗口。

## 10. 第一版边界

- 旧 Tauri / SQLite 原型数据不自动迁移；浏览器插件从自己的本地存储开始工作。
- 原壁纸恢复覆盖逐屏图片、壁纸位置模式和背景色；Windows 壁纸轮播会恢复为启用当时捕获的静态图片，不会自动重新启动轮播。
- 当前插件仍以开发者加载方式使用；助手已具备本地与 GitHub 共用的单文件安装程序构建流程。
