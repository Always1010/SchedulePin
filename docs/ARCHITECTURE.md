# SchedulePin 插件与桌面助手架构

## 1. 本次迁移的目标

SchedulePin 不再把可交互 WebView 窗口伪装成桌面组件。产品拆分为一个可以独立工作的浏览器插件，以及一个仅在需要 Windows 桌面壁纸能力时安装的本地助手。

- 浏览器插件是主产品：负责新标签页、侧边栏、任务编辑、设置和主数据存储。
- 本地助手是可选扩展：负责读取显示器、备份壁纸、生成计划壁纸、应用和恢复壁纸。
- 没有安装本地助手时，插件的任务管理、新标签页和侧边栏仍然完整可用。
- 桌面只展示，不接受鼠标操作，也不存在窗口拖动、缩放、置顶或焦点问题。

## 2. 技术栈变更

### 2.1 放弃的部分

| 技术或组件 | 原用途 | 放弃原因 |
| --- | --- | --- |
| 可见 Tauri WebView 窗口 | 同时承载任务编辑和桌面展示 | 与“桌面只展示”冲突，并产生焦点、拖动、缩放和关闭问题 |
| WorkerW / Progman 子窗口嵌入 | 模拟桌面组件层 | 属于易受 Explorer、DPI、父窗口裁剪和多屏坐标影响的窗口技巧 |
| `always_on_bottom` 窗口层级模拟 | 让组件位于应用窗口下方 | 无法像壁纸一样保证绝不出现在普通应用之上 |
| Tauri SQL 与前端直连 SQLite | 桌面窗口中的任务存储 | 浏览器插件不能直接使用这套原生插件；主数据应随插件独立存在 |
| 前端原生拖动、八方向缩放 | 调整真实桌面窗口 | 改为在浏览器的显示器预览画布中编辑布局 |
| 本地 HTTP 管理端口 | 让浏览器访问桌面程序 | 插件已经提供管理界面，Native Messaging 更窄、更安全，不必暴露端口 |

### 2.2 保留的部分

| 技术或能力 | 新用途 |
| --- | --- |
| React | 新标签页、侧边栏和设置界面 |
| TypeScript | 任务模型、插件逻辑和通信协议类型 |
| Vite | 构建 Manifest V3 插件资源 |
| Rust | 编写体积小、无编辑窗口的 Windows 助手 |
| 本地优先原则 | 默认不登录、不上传任务，数据留在本机 |
| 今日重点、日程、纪律、备忘 | 保留现有产品模型并由插件统一编辑 |

### 2.3 新增的部分

| 技术或组件 | 用途 |
| --- | --- |
| Manifest V3 | Chrome / Edge 浏览器插件运行模型 |
| New Tab Override | 打开新标签页时显示今日计划 |
| Side Panel | 浏览网页时随时打开任务面板 |
| `chrome.storage.local` | 插件的主数据源；助手缺失时仍可独立工作 |
| Extension Service Worker | 监听数据变化、定时刷新和连接本地助手 |
| Native Messaging | 插件与助手之间的受限 JSON 消息通道 |
| SVG + PNG 壁纸渲染 | 按显示器分辨率生成静态桌面计划 |
| Windows `IDesktopWallpaper` | 逐屏读取、应用和恢复壁纸 |
| 助手状态缓存 | 浏览器关闭后保留最后一次计划快照和原壁纸信息 |

## 3. 运行架构

```text
Chrome / Edge 浏览器插件
├─ 新标签页
├─ 侧边栏
├─ 设置与显示器布局预览
├─ chrome.storage.local（主数据）
└─ Service Worker
          │
          │ Native Messaging（助手可用时）
          ▼
SchedulePin Helper.exe
├─ 协议校验与能力查询
├─ 最后计划快照缓存
├─ 显示器枚举
├─ 原壁纸状态备份
├─ SVG/PNG 壁纸生成
└─ IDesktopWallpaper 调用
          │
          ▼
Windows 每块显示器的桌面壁纸
```

## 4. 数据所有权与同步

插件是唯一的任务主数据源。本地助手不能新增、修改或删除任务，只接收插件发来的渲染快照。

1. 用户在新标签页或侧边栏修改计划。
2. 插件先把变更写入 `chrome.storage.local`。
3. Service Worker 合并短时间内的连续变更，然后向助手发送最新完整快照。
4. 助手持久化快照，生成临时 PNG。
5. PNG 完整生成后原子替换正式文件，再通知 Windows 更新壁纸。
6. 失败时保留上一张有效壁纸，并向插件返回可读错误。

助手未安装或未运行时，第 3 步只把桌面状态标记为“未连接”，不会影响前两步。

## 5. 壁纸备份和恢复

第一次启用桌面计划时，助手按显示器 ID 保存：

- 原壁纸路径和一份可恢复的文件副本；
- 壁纸位置模式；
- 计划展示开关；
- 当前显示器布局。

只要原始备份已经存在，后续刷新计划不得用 SchedulePin 生成图覆盖它。用户可以执行：

- 暂时恢复原壁纸：保留助手和任务，只关闭桌面展示；
- 重新显示桌面计划：用最新计划重新生成；
- 退出并恢复原壁纸：恢复后停止助手；
- 卸载助手：先恢复壁纸，再清理注册和生成文件。

如果助手异常退出，Windows 会继续显示最后一张有效壁纸。下次连接助手后仍可使用持久化备份恢复。

## 6. 布局与多显示器

真实桌面不再接受拖动。插件设置页显示每块屏幕的比例预览，计划卡片在预览中使用百分比坐标：

```json
{
  "x": 0.68,
  "y": 0.06,
  "width": 0.28,
  "height": 0.82
}
```

助手收到快照后，把百分比转换为对应显示器的物理像素。因此更换分辨率或缩放比例后，布局仍保持相同的相对位置。用户可以指定单屏、全部屏幕，并为每块屏幕保存独立布局。

## 7. 可选安装模型

### 仅插件

- 不安装任何本地程序；
- 新标签页、侧边栏和任务管理正常使用；
- 桌面设置显示“未安装助手”；
- 不读取或修改 Windows 壁纸。

### 插件 + 助手

- 助手安装在 `%LOCALAPPDATA%\SchedulePin`；
- Native Messaging 清单只允许指定的扩展 ID 访问；
- 插件检测成功后解锁桌面设置；
- 助手安装包在开发阶段保存在本地，发布阶段可以托管到 GitHub Releases。

## 8. 安全边界

- 不开放局域网或公网端口。
- Native Messaging Host 使用 `allowed_origins` 限制扩展 ID。
- 助手只接受固定协议中的查询、同步、应用和恢复命令。
- 任务内容不会由助手上传。
- 生成文件、缓存和壁纸备份均保存在当前用户的本地应用数据目录。

## 9. 第一版验收标准

- 插件可作为未打包 Chrome / Edge 扩展加载。
- 新标签页与侧边栏都能管理同一份任务数据。
- 未安装助手时插件无报错并显示清楚的可选安装状态。
- 安装助手后插件能读取显示器列表。
- 插件保存计划后助手自动生成并应用新壁纸。
- 单屏和全部屏幕模式均可生成壁纸。
- 关闭桌面展示能恢复启用前的逐屏壁纸。
- 浏览器布局预览支持移动和缩放计划卡片。
- 本地助手不创建任何可见编辑窗口。
